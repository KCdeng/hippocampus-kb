# 闭环写入方案（v0 提案，待审）— 让海马体从"只读"变"读写"

## 目标
智能体在任务结束/纠错发生时，把结论写入海马体；下次检索能召回"自己产出的知识"，并知道它的来源、置信度与新旧关系。对应生物学功能：巩固（consolidation）+ 衰减（forgetting）。

## 设计（三个动作 + 一个闸门）
### A1. remember(query, answer, sources[], confidence)
- 新存储区 `kb/mem/`（与原始文档隔离，`source_type: "agent"`）；
- 写入即切块→嵌入→追加进 vec/mem 子索引（mem 索引独立文件，检索时合并候选）；
- 元数据：时间戳、任务引用、被引来源（原库 chunk_id）、confidence(0~1)、版本号。

### A2. correct(old_mem_id, new_answer)
- 不删除：旧记忆打 `superseded_by` 指针，检索时对 superseded 记忆分数 ×0.3（衰减而非遗忘）；
- 冲突检测：写入前对 mem 区做一次相似检索，top1 相似度 >0.85 视为"同一事实更新"，走 A2。

### A3. consolidate(周期任务)
- 每周把同主题多条记忆交给 LLM 归并成 1 条摘要记忆（保留全部 source 链），原始条目转 dormant；
- 在 NAS 引擎空闲窗口跑，成本以条计，可控。

### G. 质量闸门（必须先于 A1 上线）
- 评测集扩展 mem 题：金标准加 10~15 条"应召回 agent 记忆"的题；
- 判据：写入后这些题 hit@5 ≥80%，且原库题命中率**不下降**（污染检验：融合检索不排除噪声记忆）；
- 不达标 → 只保留检索融合为"文档优先、记忆其次"的分层返回，不混合排序。

## 接入方式（给 Qoder 智能体）
1. MCP 工具 2 个：`kb_search` / `kb_remember`（参照 src/mcp-memory-service-main 的 server 骨架，后端直接调我们的 KB 类——预计 150 行内）；
2. 过渡方案（零代码）：AGENTS.md 规定任务收尾跑一行 `--serve` 的 remember 命令。

## 工作量与顺序
| 步骤 | 估时 | 前置 |
|---|---|---|
| mem 区 + A1/A2 写入与衰减 | 半天 | 无 |
| MCP server 包装 | 半天 | A1 |
| 评测扩展 + 闸门试验 | 半天 | A1/A2 |
| A3 周期巩固 | 1 天 | 闸门通过 |

## 明确不做
- 不自训嵌入模型（理由见昨日结论：开源涨代快，自研纯亏）；
- 不让记忆参与文档区排序权重竞争（分层返回优先）；
- 不自动写入低置信度(<0.5)结论——宁可让智能体说"不确定"。
