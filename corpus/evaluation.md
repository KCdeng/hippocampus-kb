# 评测：闸门写在文件里，不写在延长线记忆里

`eval.py` 读一份金标准（`eval_set.json`：问题、期望文件、期望原文锚点、题型），
对每种检索档跑同一批题，输出 hit@1 / hit@3 / hit@5 / MRR / 文件级@5。

## 判定的两个层次

**严格命中**要求答案块**既是期望文件、又真的含那段原文**；文件级命中只要求排进前 5 的文件对。
前者证明"查得到并能溯源"，后者证明"没跑偏到别的文档"。两个都要看：只看文件级会掩盖行号丢失，
只看严格会低估"换了一篇同主题文档"的实际可用性。

同一文件的判定允许一方是另一方的相对子路径，但**必须落在目录边界上**。
裸 `endswith` 会把 `myfoo.md` 判成 `foo.md` 的命中——文件名后缀相同就算命中，分数会虚高。

## 三条防止"看起来退化了"的硬规矩

1. **档位由评测脚本自己钉死。** 不设 `KB_VEC` / `KB_MODEL` 时检索层会静默退到陈旧的小模型档，
   形状合法、分数全错，测出来的数字与生产无关。
2. **gold 文件不存在就直接报错退出。** 文档搬家会让那道题永远判负，
   看起来像检索退化——这是评测集的问题，必须显式失败。
3. **闸门判据在 `baseline.json` 里，机器比对。** eval 结束自动给 PASS/FAIL，不过闸 exit 1。
   阈值用精确分数而不是四舍五入值：文档里写 96.4% 曾把闸门抬到 0.964，
   导致正确的基线被判 FAIL。

## 日常跑法

跑全部档（含耗时档）可能要半小时以上，日常回归只跑 grep / bm25 / vec / hybrid / hybrid-v2 五档。
逐题明细按时间戳落 `eval_per_query_*.json`，不互相覆盖——换档前后要能对比同一题的名次。
另有一个真实流量回放工具（`replay.py`）：改动前后各存一份快照，比较 top-5 集合与分数漂移；
回放请求带 `replay:true`，**不写查询日志、不计命中**，否则评测会把使用统计污染成噪声。

## 已证伪的杠杆（别再重复踩）

| 方案 | 结果 | 死因 |
|---|---|---|
| 表格按行组袋 + 标题并正文 | hit@5 −3.6pp | BM25 涨了但 dense 掉得更多 |
| 每行追加「列名=值」标签 | 出局 | 词面 +1.8pp 撑不住块数 +8% 的候选稀释 |
| 表格块挂上方散文窗 | 零名次变化 | 语料普查显示四条件联合命中 0 张表，**没有作用对象** |
| cross-encoder 精排 | −21.8pp 且慢 22 倍 | 精排与前级排序分歧，挤掉正确答案 |
| 语义切块 / 固定 overlap | 出局 | 负数据显示切块边界收益不稳定 |

私有语料上的完整实测记录在 `kb/baseline_privatedomain.json` 与 `CHUNKING-EVIDENCE.md`。
